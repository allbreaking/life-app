# Life-OS MVP 架构

## 形态

无构建依赖的单页本地应用。HTML/CSS 负责视图，JavaScript 维护规范化状态，并通过版本化 `localStorage` 适配器持久化。

## 状态模型

- `tasks`：统一任务实体，包含 `sourceModule`、`quadrant`、排期和完成状态。
- `eodEntries` / `readInbox`：EOD 的计划生成工作任务，收获生成待筛选知识条目。
- `transactions` / `budget`：必要支出与待结算支出分离。
- `watchlist` / `positions`：持仓只保存 `watchlistId` 外键。
- `principles` / `changelog` / `items` / `people` / `learningDomains`：模块实体。

## 数据流

```text
页面表单 / 快捷录入
        ↓ 校验
领域动作（修改单一状态树）
        ↓
localStorage 持久化
        ↓
派生选择器 → 九模块视图 / 总览 / 预警
```

## 日程排期交互

- 待排期池只是按 `sourceModule` 分组后的任务引用视图。
- 拖拽载荷只包含稳定的任务 ID；放置目标提供日期以及可选时间段。
- 放置动作更新任务的排期字段并重新渲染，禁止在日程模块创建第二份任务内容。
- 已排期卡片使用同一任务 ID 作为拖拽载荷；拖到新落点只更新排期字段，拖回任务池则清空排期字段。
- 日视图强调小时段，周视图强调一周负荷分布，月视图强调日期密度和跨周概览。
- 连续时间画布使用“距当天零点分钟数 → 像素位置”的纯函数映射；拖放坐标反向换算为分钟并按 15 分钟吸附。事件时长使用同一比例映射为高度。

## 安全与可靠性

- 所有外部文本通过 `textContent` 或统一 `escapeHTML` 后进入 DOM。
- 数字输入使用有限值、范围和业务关系校验。
- 存储读取失败或 schema 不匹配时回退演示数据，不阻塞启动。
- 状态写入是单键整树替换，避免跨键部分提交。
- 用户动作绑定稳定 ID；重复渲染不会重复创建业务记录。

## 后续桌面化

在 Web MVP 验证通过后，可用 Tauri 包装并把存储适配器替换为 SQLite；领域动作与状态模型保持不变。原生菜单栏、通知与行情轮询放在 Rust 侧，以显式 capability 暴露给前端。
