# 财务 500 元份数目标设计

日期：2026-08-29

## 设计选择

- 目标份数与单份金额固定在前端领域模型；SQLite 只保存会变化的已完成份数，避免冗余字段失配。
- 已完成份数使用独立标量资源 `finance.goalCompletedUnits`，不混入月度预算或交易资源，避免长期目标与月度结算互相影响。
- 输入先通过纯函数严格解析，再校验增加不超过目标、减少不低于零；只有合法操作进入资源替换链路。
- 单次资源替换由现有 `replaceDomainResource` 生成唯一 request ID，并由 Rust `command_receipt` 保证重试幂等。

## 数据流

```text
finance.goalCompletedUnits（默认 1500）
  → 纯函数派生份数百分比与金额
  → 财务页进度卡

手动输入变动份数 + 选择增加/减少
  → 严格正整数校验
  → 结果保持在 0–3000 校验
  → setGoalCompletedUnits
  → typed IPC 白名单
  → Rust 单资源事务替换
  → SQLite domain_value + command_receipt
```

## 实施计划

3. 在财务页加入进度卡、可访问进度条和手动增加表单。
4. 添加组件回归测试与响应式样式。
5. 同步现状需求、入口 Map、总规格和进度，执行完整验证。
