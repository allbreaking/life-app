# 投资观察列表原地管理 Architecture

## 最后更新：2026-08-16

## 数据流

```text
观察行“编辑”
  → 同一 watch-row 切换为输入控件
  → 六位代码/名称/目标价关系/重复代码校验
  → 代码未变：保留 current 与 quoteAt
  → 代码变化：固定新浪 adapter 取新代码最近行情
  → 按稳定 id 替换 trade.watchlist
  → SQLite

观察行“删除”
  → 检查 trade.positions 中全部当前/已清仓记录
  → 有引用：拒绝并保留记录
  → 无引用：按稳定 id 过滤 trade.watchlist
  → SQLite
```

## 组件责任

- `WatchRow` 持有单行草稿、编辑态和保存中状态；编辑态仍使用同一个 `.watch-row` 网格容器。
- `WatchRow` 关闭浏览器阻断式原生校验；父组件返回统一校验/行情错误，当前行负责展示并保留草稿，使每次保存点击都有明确结果。
- `Trade` 负责跨记录重复校验、持仓引用保护、必要的行情请求和领域资源替换。
- 行情轮询继续只更新 `current` 与 `quoteAt`；用户编辑不改变该职责。
- 持仓继续用 `watchlistId` 引用稳定观察标的 ID，编辑代码或名称不破坏关联。

## 副作用、幂等与安全

- 打开编辑、输入、取消和客户端校验无外部副作用。
- 未改代码的保存只执行一次既有领域资源替换；改代码的保存先执行固定主机只读行情请求，再执行资源替换。
- 删除仅在无持仓引用时执行资源替换；不级联删除持仓或清仓历史。
- 所有代码、名称和价格在网络/存储边界前校验；代码仍为六位数字，名称由 React 文本节点渲染。
- 不新增 SQL、shell、通用网络入口、capability、依赖或数据库迁移。

## 验证结论

- 规格一致性：观察列表编辑保持在原网格行，现价/行情时间只读，删除执行全部持仓引用保护。
- 副作用一致性：瞬时编辑与取消不写资源；保存和无引用删除只使用既有领域资源替换，代码变化才触发行情请求。
- 自动校验：47 项前端测试、16 项 Rust 测试、TypeScript、静态规格、生产构建与发布资源预算通过。
- 真实页面：本地浏览器确认编辑态仍为 `.watch-row`，输入框计算边框为 `0px`，行宽未超过卡片，取消恢复且控制台无错误。
