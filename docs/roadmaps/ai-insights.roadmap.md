# AI 总结分析模块 Roadmap

路线图版本：2026-08-16

状态：ROADMAP 草案，等待人工审查；未授权进入 BUILD。

## 入口判断

- 预计涉及前端 AI 模块、Rust/Tauri 服务、SQLite、文件导出、外部模型服务和系统凭据存储，超过 3 个文件且跨越 2 个以上子系统。
- 完整交付预计超过 2 小时，并新增文件与网络副作用。
- 结论：大功能，按 `ROADMAP → DESIGN → PLAN → BUILD → VERIFY` 推进；本轮只完成 ROADMAP、SPEC 与 ARCH 文档。

## 产品目标

在不破坏 Life-OS 本地优先原则的前提下，把用户明确选择的领域数据转换为可预览、可脱敏、可追溯的 AI 上下文，用于生成周期总结、趋势发现、风险提示和下一步建议。

首个验证场景是“每周 Life Review”：聚合一周内的工作重点、日程完成情况、财务概况、学习进展和用户复盘，输出本周摘要、主要变化、潜在失衡和下周最多三项行动建议。

## 路线原则

1. 同一套 `AI Context` 同时服务文件导出和模型 API，避免两条数据口径分叉。
2. 默认最少披露：默认关闭社交原文、财务备注、投资仓位明细等高敏感字段，由用户逐项开启。
3. 发送前可见：任何文件写出或网络发送前，用户都能看到模块、时间范围、敏感级别和准确正文预览。
4. 确定性事实优先：金额汇总、完成率、趋势和异常阈值由本地代码计算；模型负责解释，不负责重新计算账目。
5. AI 首期只读：报告不得自动修改任务、预算、联系人、投资数据或其他领域资源。
6. 结论可追溯：每条重要发现引用稳定的本地证据 ID 或聚合项，不把无依据推断表现成事实。
7. Provider 可替换：模型供应商、模型名和 API 形态不进入领域数据模型。

## P7-0：数据语义就绪

当前领域资源并不都保存历史时间：日程和投资复盘可按日期筛选，而工作任务、学习进度、人生原则、财务累计值等部分资源主要表示“当前状态”。因此周报不能把当前快照伪装成一周内发生的事件或趋势。

在 P7-A BUILD 前必须完成：

- 为所有允许进入 Context 的字段标注 `period_event` 或 `current_snapshot` 时间语义。
- 周报仅对带可靠业务日期的记录做周期筛选、完成率和趋势计算。
- 当前状态可以作为报告背景，但必须标为“截至快照时间”，不能用于声称本周新增、减少或变化。
- 对缺少历史数据的模块输出明确 limitation；需要趋势时，先通过独立规格补齐业务时间戳或历史快照，不能由 AI 猜测。

## P7-A：AI Context 与手动导出

### 范围

- 新增“AI 洞察”入口及“每周 Life Review”配置页。
- 用户选择日期范围、参与模块和脱敏策略。
- 本地构建标准化 AI Context，展示将要导出的准确内容、记录数量和敏感字段提示。
- 支持导出 UTF-8 Markdown 与版本化 JSON；两种格式表达同一份事实和分析任务。
- 导出文件只在用户确认并选择位置后写入；取消、预览和校验不产生文件。

### 阶段门禁

- 导出内容不包含 API Key、数据库路径、内部收据、软删除记录或未选择模块。
- 同一数据快照和配置生成相同 `contextHash`，Markdown 与 JSON 的证据 ID 一致。
- 周期事件与当前快照有机器可读标识；没有历史依据时不输出“本周变化”类确定性指标。
- 用户至少实际使用数次周报导出，并确认字段选择与报告结构有持续价值，再进入 P7-B。

## P7-B：应用内模型 API

### 范围

- 在 Rust 侧增加白名单模型 Provider adapter；首版只启用一个经人工确认的供应商，不接受任意 Base URL。
- 支持用户自带 API Key；密钥进入操作系统凭据存储，不进入 React、SQLite、日志、导出文件或错误消息。
- 发送前继续复用 P7-A 的准确载荷预览；只有用户点击“生成分析”才发起网络请求。
- 模型返回严格结构化报告，经本地 schema 校验后展示；无效响应不保存为正式报告。
- 保存报告正文、证据引用、模型元数据、提示词版本、`contextHash` 和生成时间；默认不保存完整发送载荷副本。

### 阶段门禁

- 网络域名、超时、响应体大小和重试次数受固定策略约束。
- 用户内容以不可信数据处理，不能改变系统指令、调用工具或触发业务命令。
- 对失败、超时、限流、鉴权错误和“结果未知”的计费边界有明确反馈，未经确认不自动重复可能计费的请求。
- 报告中的关键结论具有合法证据引用；投资内容始终带非投资建议提示。

## P7-C：历史、比较与自动提醒

### 范围

- 查看历史周报、月报，比较相邻周期的确定性指标和 AI 解释。
- 增加单模块深度分析：工作负荷、财务节奏、学习进展；投资模块只做复盘总结，不输出确定性买卖指令。
- 可选的本地提醒提示用户生成报告；默认不在后台自动向外部模型发送数据。
- 用户可删除报告、清除模型配置和系统凭据。

### 阶段门禁

- 历史报告删除与备份恢复行为明确且经过测试。
- 比较指标由本地确定性代码产生，不依赖模型记忆上一次对话。
- 若未来增加自动发送，必须作为新的独立规格进行人工审查，不能由“提醒”隐式升级。

## P7-D：可选建议落地（不在当前授权范围）

只有在只读分析长期验证后，才评估把某条建议转换为任务草稿。即使实施，也必须逐条预览、由用户确认，并调用既有领域命令；禁止模型直接写数据库、批量执行或发起交易。

## 明确非目标

- 通用聊天机器人、长期自由对话记忆和网页搜索。
- 首期向量数据库、Embedding、云端同步或上传整个 SQLite 数据库。
- AI 自动修改领域数据、自动发送报告、自动交易或代替专业财务/医疗/法律判断。
- 任意自定义 API 主机、任意模型工具调用、shell、SQL 或文件系统访问。
- 以模型输出替代本地金额计算、任务状态判断和业务约束。

## 产品评估指标

- 用户是否愿意连续四周生成 Life Review。
- 报告中被认为有帮助的发现比例，以及无依据或重复建议比例。
- 每次发送前被用户关闭或脱敏的字段类型，用于改进默认策略但不记录原始敏感正文。
- 构建失败率、API schema 校验失败率、API 成本和响应时间。
- 任何未预期数据外发、密钥泄漏或 AI 自动写业务数据均视为阻断级缺陷。

## 人工审查点

- 是否同意以“每周 Life Review”作为首个场景，而不是通用聊天。
- 是否同意 P7-A 先只做可预览的 Markdown/JSON 手动导出。
- 是否同意 P7-B 首版采用 BYOK、固定 Provider、手动触发，并默认不保存完整发送载荷。
- 是否同意社交原文、财务备注和投资仓位明细默认关闭。
- 是否同意任何自动修改数据能力延后到独立的 P7-D 审查。
