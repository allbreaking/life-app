# 投资观察列表原地编辑与删除函数级规格

规格版本：2026-08-16

## 入口自检

- 涉及文件数：预计 7 个。
- 涉及模块数：1 个业务模块（投资）；沿用既有行情与领域资源接口。
- 预计工作量：少于 2 小时。
- 建议入口：新功能，完成 DESIGN 后进入 PLAN；用户已直接授权实现。

## 函数：Trade()
**所在文件**：`src/features/trade/Trade.tsx`
**输入**：
  - 无显式参数；读取观察列表、持仓及观察行提交/删除事件。
**输出**：`JSX.Element` - 带观察列表原地管理能力的投资模块界面。
**副作用（完整列表，没有写“无”）**：
  - 打开、输入、取消观察标的编辑时只更新对应观察行的前端瞬时状态。
  - 保存未修改代码的合法编辑时，按稳定观察标的 ID 替换 `trade.watchlist` 中代码、名称、乐观/中枢/悲观目标价和安全价，并通过 typed IPC 幂等写入 SQLite。
  - 保存已修改代码的合法编辑时，先向既有固定新浪行情 adapter 请求新代码的最近行情；成功后连同新现价与行情时间替换同一观察标的并持久化。
  - 删除无持仓引用的观察标的时，按稳定 ID 从 `trade.watchlist` 移除并持久化。
  - 更新页面内反馈消息和保存中的行内状态。
**不应该做的事**：
  - 不得在独立页面、弹窗或列表外表单中编辑。
  - 不得允许用户编辑现价、行情时间或派生告警状态。
  - 不得在输入、取消、校验失败、重复代码或行情失败时写入观察列表。
  - 不得删除被当前持仓或已清仓记录引用的观察标的。
  - 不得改变观察标的稳定 ID，或把用户输入拼接进 SQL、shell 和任意 URL 主机。
**异常处理**：
  - 非六位代码、空名称、超长名称、非有限价格和非法价格关系显示中文错误并保持编辑态。
  - 与其他观察标的代码重复时显示错误并保持编辑态。
  - 改代码后的行情无结果或请求异常时保留原记录并保持编辑态。
  - 删除存在任意持仓引用的标的时拒绝删除并显示原因。
**依赖的外部资源**：
  - `trade.watchlist`、`trade.positions` 领域资源。
  - 固定主机新浪行情 adapter 与既有 typed IPC。
**幂等性**：部分是 - 按稳定 ID 的集合替换可安全重试；相同有效内容重复保存得到相同业务值；改代码可能重复请求只读行情，但不创建新观察标的。

## 函数：WatchRow({ item, onSave, onDelete })
**所在文件**：`src/features/trade/Trade.tsx`
**输入**：
  - `item`：`Watch` - 已规范化观察标的。
  - `onSave`：异步回调 - 提交稳定 ID 与用户可编辑字段；成功返回 `null`，失败返回可展示的中文原因。
  - `onDelete`：回调 - 请求按稳定 ID 删除。
**输出**：`JSX.Element` - 展示态或位于同一网格行内的编辑态。
**副作用（完整列表，没有写“无”）**：
  - 编辑、输入、保存中状态和取消仅更新该组件瞬时状态。
  - 点击保存始终进入应用校验；校验或行情失败时在当前编辑行展示原因。
  - 保存与删除分别委托父组件回调；组件本身不直接访问存储或网络。
**不应该做的事**：
  - 不得在保存失败时退出编辑态。
  - 不得用草稿覆盖 `item.current`、`item.quoteAt` 或稳定 ID。
  - 不得发起行情、存储、shell 或文件请求。
**异常处理**：
  - Escape 等同取消并恢复进入编辑前的值。
  - 表单关闭浏览器原生阻断式校验，由父组件统一校验并返回原因，避免提交事件被静默拦截。
  - 保存回调返回错误字符串时保留当前草稿并在原行显示，允许用户修正。
  - 保存过程中禁用重复提交与取消动作。
**依赖的外部资源**：
  - 无直接外部资源；父组件负责行情和持久化。
**幂等性**：是 - 相同属性和瞬时状态产生相同渲染；业务写入由父组件负责。

## 数据与兼容边界

- 不新增字段，不迁移数据库；继续使用既有 `trade.watchlist` JSON 资源和稳定 `id`。
- 可编辑字段为 `code`、`name`、`optimisticTarget`、`target`、`pessimisticTarget`、`safety`。
- `current`、`quoteAt` 与告警状态由行情及纯派生逻辑维护，不作为用户输入。
- 修改代码不会改变持仓的 `watchlistId`；删除前检查全部持仓（包括已清仓），避免形成界面不可见的孤立引用。

## 验收测试要求

- 组件测试：点击编辑后输入控件位于原 `.watch-row`，有效内容保存后原行更新并退出编辑态。
- 组件测试：取消恢复原值；非法价格关系与重复代码保持编辑态且不更新资源。
- 组件测试：原生无效输入仍触发应用校验，并在当前 `.watch-row` 内显示错误原因，不表现为按钮无响应。
- 组件测试：删除无引用观察标的后从列表和持仓选择器移除。
- 组件测试：被当前或已清仓持仓引用的观察标的拒绝删除。
- 组件测试：现价和行情时间不出现可编辑控件；修改代码时只有行情成功才替换原记录。
- 样式验证：原地编辑输入框常态无边框，`focus-visible` 使用背景变化，行内操作不会破坏现有网格滚动边界。
