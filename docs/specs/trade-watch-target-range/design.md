# 投资观察列表三档目标价设计

## 功能拆分

- F01：观察标的数据模型兼容——保留原 `target` 字段并将其语义改为中枢目标价，新增 `optimisticTarget`（乐观目标价）与 `pessimisticTarget`（悲观目标价）。
- F02：观察列表录入与展示——新增三档目标价输入和列展示，原“目标价”文案统一改为“中枢目标价”。
- F03：预警与持仓指标语义——已有目标价预警、持仓“距目标价”继续以中枢目标价计算，并将界面文案明确为“中枢目标价”。
- F04：兼容与自动校验——旧记录缺少新增字段时以中枢目标价兼容读取；覆盖字段顺序、输入关系、旧数据和派生指标回归测试。

## 入口判断

- 涉及文件数：预计 7 个（设计/规格、功能规格、架构、投资组件、模型或兼容函数、样式、测试、总进度中按实际合并计算）。
- 涉及模块数：1 个（投资模块；领域资源持久化接口不变）。
- 预计工作量：少于 2 小时。
- 结论：新功能、单段交付；先 DESIGN，经人工审查后进入 PLAN。

## 单段计划

- 单段：完成观察列表三档目标价的数据兼容、录入、展示、文案调整与回归测试。
- 完成标准：
  - 新增观察标的必须提供有限正数的乐观、中枢、悲观目标价，并满足 `optimisticTarget >= target >= pessimisticTarget > 0`。
  - 安全价继续满足 `0 <= safety < target`，其语义和预警不变。
  - 原 `target` 字段不改名，所有用户可见文案改为“中枢目标价”。
  - 旧记录仅含 `target` 时可正常加载；兼容读取时乐观、悲观目标价均回退为中枢目标价，且后续正常资源写入可持久化完整结构。
  - 目标价预警与持仓目标价距离继续使用中枢目标价，不因增加估值区间改变既有业务行为。
  - 类型检查、前端自动测试、静态规格校验和生产构建通过。

## 关键技术决策

- 保留字段 `target`：已有 `trade.watchlist` JSON 资源和持仓派生逻辑直接使用该字段；保留字段可避免破坏既有 SQLite 用户数据，并把变更限制在投资模块内。
- 新增字段命名为 `optimisticTarget`、`pessimisticTarget`：字段含义明确，避免使用依赖列顺序的数组结构。
- 旧数据兼容采用确定性回退：缺字段时两档新目标价均取 `target`。该策略不凭空推断用户估值，同时保证旧记录可展示、可参与后续写入。
- 不新增数据库迁移：`trade.watchlist` 通过现有领域资源 JSON 持久化；仍使用同一资源键和幂等替换事务。
- 既有预警以中枢价为阈值：用户只要求增加估值档位，没有要求改变告警规则；不把乐观或悲观目标价隐式变成交易信号。

## 数据接口

```ts
type Watch = {
  id: string;
  code: string;
  name: string;
  target: number;              // 中枢目标价；原字段，保持向后兼容
  optimisticTarget: number;    // 乐观目标价
  pessimisticTarget: number;   // 悲观目标价
  safety: number;
  current: number;
  quoteAt?: string;
};
```

兼容输入允许 `optimisticTarget`、`pessimisticTarget` 缺失；进入组件运行态前将缺失值规范化为 `target`。规范化函数为纯函数，不写存储、不发网络请求。

## 副作用边界

- 三档目标价输入、校验失败和表单草稿：只影响浏览器表单或状态消息，不写 SQLite，不发行情请求。
- 新增观察标的：仍会调用固定域名新浪行情 adapter 获取最近价格；成功后通过 `trade.watchlist` 领域资源替换写入 SQLite，失败不创建记录。
- 旧数据规范化：读取阶段只转换内存值；不单独触发写入。下一次既有观察列表资源成功写入时，完整规范化结构随资源一起持久化。
- 行情轮询：只更新 `current`、`quoteAt` 并保留三档目标价；网络和持久化副作用沿用既有声明。
- 展示、预警和持仓距离计算：纯派生，无存储、网络、文件或 shell 副作用。

## 安全与异常边界

- 三档目标价必须是有限正数，拒绝 `NaN`、无穷值、零和负数。
- 股票代码仍仅接受六位 A 股代码；名称沿用长度约束并由 React 文本节点渲染。
- 价格关系不合法时仅展示页面内校验消息，不调用行情服务、不修改观察列表。
- 不新增通用网络 capability，不拼接 shell 命令或 SQL。

## 人工审查重点

- 是否认可三档目标价的顺序约束：乐观 ≥ 中枢 ≥ 悲观。
- 是否认可安全价继续只要求低于中枢目标价，而不强制低于悲观目标价。
- 是否认可旧记录的乐观价和悲观价均以中枢价回退，直到用户未来重新录入或编辑。
- 是否认可既有告警和持仓距离仍以中枢目标价计算。
