# 投资观察列表四维评分与排版设计

日期：2026-08-30

## 入口判断

- 涉及文件数：规格、架构、模型、组件、样式、测试与现状文档共 8 个以上。
- 涉及模块数：仅投资模块；不新增领域资源、IPC、网络接口或数据库表。
- 预计工作量：少于 2 小时。
- 结论：新功能，按 DESIGN → PLAN → BUILD → VERIFY 单段交付；用户已直接授权实现。

## 功能拆分

- F01：观察标的内嵌商业模式、盈利能力、财务稳定性、现金流四个可选评分；移除当前估值和分红评分。
- F02：每项评分只接受 0–5 的整数；新增和原行编辑均允许留空，留空表示“未评分”，0 分是有效评分。
- F03：新增区和观察列表展示均不提供安全价；新标的固定保存 `safety: 0`，新增只校验三档目标价。安全价继续保留在已有标的编辑、价格状态和持仓指标派生中。
- F04：列表以四行紧凑星级展示评分；已评分显示对应实心/空心星，未评分显示“未评分”。
- F05：默认按加入时间倒序，最新加入的标的置顶；排序控件可改选任一评分维度并切换高到低或低到高。
- F06：新增输入和评分下拉复用项目既有浅底、无边框、圆角与可见焦点风格；观察表格缩短名称列并均衡价格、评分和操作列。

## 单段计划

1. 扩展 `trade.watchlist` 内嵌 schema 与旧数据读取兼容。
2. 添加四项可选评分解析、最新加入优先和评分稳定排序纯函数及边界测试。
3. 为新增表单和观察标的原行编辑保留四项非必填评分。
4. 统一新增输入/评分下拉样式，均衡表格列宽，并在筛选后、分页前排序。
5. 同步现状需求、入口 Map、总规格与进度，执行完整验证。

## 关键决策

- 四项评分直接内嵌在既有 `trade.watchlist` 实体中，避免跨资源提交和数据库迁移。
- 旧 `cashFlowDividendRating` 在读取时兼容为 `cashFlowRating`；旧 `valuationRating` 读取后丢弃，不主动回写兼容结果。
- 旧记录缺少评分时只在内存规范化为 `undefined`，不主动回写；后续用户保存该记录时随完整实体持久化。
- 新增标的写入 ISO 8601 `createdAt`；旧记录没有时间时以原数组顺序的后项视为较新。数据管道为搜索 → 状态/标签筛选 → 默认时间倒序或评分排序 → 分页。
- 排序使用副本，禁止修改领域资源数组；未评分固定置后，避免切换方向时空值跑到列表顶部。
- 安全价从新增区和观察列表展示中移除；新增记录以 `safety: 0` 兼容既有 schema，已有标的编辑、告警与持仓风控计算语义保持不变。

## 副作用边界

- `normalizeWatch`、评分解析、星级格式化、时间倒序与评分排序：纯函数，无存储、网络、文件或系统副作用。
- 排序维度、排序方向和页码：只更新 React 瞬时状态，不写 SQLite。
- 新增标的：延续既有固定新浪主机行情请求；成功后通过 `trade.watchlist` typed IPC 幂等替换写入 SQLite。
- 编辑评分：不触发行情请求；只有股票代码变化时延续既有取价副作用，成功后替换 `trade.watchlist`。
- 行情刷新：只替换 `current`、`quoteAt`，对象展开保留全部评分。

## 安全与异常边界

- 外部持久化数据由 Zod 限制四项评分为 0–5 整数或缺省，`createdAt` 为 ISO 8601 时间或缺省；表单值只接受空字符串或十进制整数 0–5。
- 评分文本由 React 渲染，不接受 HTML，不拼接 SQL、shell、文件路径或网络地址。
- 非法评分保留当前编辑草稿并就近反馈，不请求行情、不写观察列表。
