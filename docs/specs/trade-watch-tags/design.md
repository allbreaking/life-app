# 投资观察列表标签设计

## 功能拆分

- F01：观察标的标签模型——每个观察标的保存 0–10 个标签，单个标签 1–20 字；旧记录缺少标签时兼容为空数组。
- F02：标签录入与编辑——新增和原行编辑均可通过中英文逗号分隔录入标签，保存前去空白、去空项并按首次出现顺序去重。
- F03：标签展示与筛选——观察行就近展示标签；状态筛选与标签筛选取交集，并继续在筛选后分页。
- F04：自动校验——覆盖旧数据兼容、标签规范化、组合筛选、编辑保存和分页重置。

## 入口判断

- 涉及文件数：预计 8 个以上（设计/规格、架构、需求、组件、模型、样式、测试、进度）。
- 涉及模块数：1 个业务模块（投资）；不新增领域资源、IPC 或数据库迁移。
- 预计工作量：少于 2 小时。
- 结论：新功能，按 DESIGN → PLAN → BUILD → VERIFY 单段交付；用户已直接授权实现。

## 单段计划

1. 以 `trade.watchlist` 内嵌 `tags: string[]` 扩展观察标的，并兼容旧记录。
2. 为新增表单和原行编辑补充标签输入、校验与持久化。
3. 动态汇总现有标签，新增标签筛选，并与价格状态筛选组合后再分页。
4. 更新需求、规格、入口索引、进度和自动测试，执行完整前端验证与生产构建。

## 关键决策

- 标签属于观察标的自身，直接内嵌在既有 `trade.watchlist` 资源，不创建全局标签库，避免跨资源部分提交。
- 标签名称按用户输入原文精确匹配；去除首尾空白并去重，不进行大小写或同义词推断。
- 空字符串代表“全部标签”，因此用户标签不能为空；标签筛选只影响观察列表展示，不影响行情刷新、持仓选择器和引用保护。
- 状态筛选保留 `all | target | watching | safety`，安全状态用户文案统一为“已跌破安全价”。

## 副作用边界

- 标签解析、规范化、状态/标签组合筛选和分页：纯函数，无存储、网络、文件或系统副作用。
- 标签筛选和页码：只更新 React 瞬时状态，不写 SQLite。
- 新增/编辑标签：随完整观察列表通过 `trade.watchlist` 既有 typed IPC 幂等替换写入 SQLite。
- 旧数据兼容：只在读取时于内存补 `tags: []`，不主动触发迁移写入。
- 行情刷新：继续只替换 `current`、`quoteAt`，对象展开保留标签。

## 安全与异常边界

- 标签由 React 文本节点渲染；不接受 HTML，不拼接 SQL、shell 或网络地址。
- 最多 10 个标签，单个标签 trim 后为 1–20 字；超限时保留当前草稿并就近反馈，不发起行情请求、不写观察列表。
- 标签筛选值只来源于当前已加载观察列表；标签删除后若筛选值失效，自动回到“全部标签”。
