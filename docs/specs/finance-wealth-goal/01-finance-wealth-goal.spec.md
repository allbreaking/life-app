# 财务 500 元份数目标规格

> 状态：已确认（依据用户 2026-08-29 指令）  
> 范围：财务模块进度展示与手动增加

## 目标

- 在财务页展示一条长期积累进度：目标为 3000 份，每份 500 元。
- 首次使用时当前进度为 1500 份，即 50%，对应 ¥750,000 / ¥1,500,000。
- 用户可输入本次变动的份数并手动增加或减少，结果在应用重启后保留。

## 交互与校验

1. 进度卡展示当前份数、目标份数、完成百分比、当前金额和目标金额。
2. 进度条使用原生 `progressbar` 语义，取值范围为 0–3000；视觉宽度封顶 100%。
3. “本次变动份数”只接受十进制正整数，不接受 0、负数、小数、指数、空白或超出安全整数的输入。
4. 本次增加不得使累计进度超过 3000 份，本次减少不得使累计进度低于 0 份；非法输入保留原进度并显示状态消息。
5. 合法操作后清空输入框、更新进度，并显示本次增加或减少的份数与折算金额。
6. 达到 3000 份后禁用“增加进度”，但仍允许减少；达到 0 份后禁用“减少进度”，但仍允许增加。

## 数据与副作用

- 新增标量领域资源 `finance.goalCompletedUnits`，类型为 `0..3000` 的整数；资源缺失时使用用户给定的 1500 份初始化。
- `Finance` 读取该资源；合法提交调用一次 `setGoalCompletedUnits`，由 `useDomainResource` 经 typed IPC 以新 request ID 幂等替换 SQLite `domain_value`。
- 输入、校验和进度派生函数无外部副作用；非法增加或减少不写 IPC、SQLite、网络、剪贴板或通知。
- 固定目标 3000 份与单份 500 元为产品常量，本次不提供修改入口。

## 验收

- 默认显示 `1500 / 3000 份`、`50%`、`¥750,000 / ¥1,500,000`。
- 手动增加 10 份后显示 `1510 / 3000 份`，并折算本次增加 ¥5,000。
- 从 1510 份手动减少 10 份后恢复为 `1500 / 3000 份`；超过当前份数的减少操作被拒绝。
- 自动测试覆盖进度派生、严格正整数解析、增减边界、组件操作和资源白名单。
- 类型检查、前端测试、Rust 测试、静态规格校验与生产构建通过。
