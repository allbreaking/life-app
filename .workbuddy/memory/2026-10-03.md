## 发布预算修复（同日，用户报 release:audit 失败）

用户报 `npm run release:audit` 失败：入口 JS 379807 B > 368640 B。

### 诊断
用 `git worktree add /tmp/life-os-base HEAD` + 软链 node_modules 建基线构建对比：
HEAD = JS 357483 / CSS 25588 / gzip ~112046（**CSS 只剩 12 B 余量**，等于锁死）；
工作区 = JS 378800 / CSS 32701 / gzip ~119386。三项全超。
扫描全量 CSS 只有 3 个未引用类（2 个动态拼接误报）→ 无可回收死代码；JS 要砍 10 KB 只能删功能。
结论：门禁已不匹配真实体量，需上调。

### 顺带修掉的真 bug
`useDomainResource(..., demoBills())` 直接求值导致生产包混入演示数据
（`ChatGPT Plus`/`买猫粮`/蓝牙耳机/视频会员 等），会触发审计第 68 行 fixture 扫描。
改成 `import.meta.env.PROD ? [] : demoBills()` 让 Rollup 静态消除；
另外 `placeholder="备注，如 买猫粮"` 也含 fixture 词，改为 `"备注"`（测试同步）。
> 约定：演示 fixture 必须走 `import.meta.env.PROD ? 空值 : fixture` 分支，不能作为实参直接调用函数，否则进生产包。

### 预算调整（已征得 doremi 确认）
`tests/verify-release.mjs` limits → js 384*1024 / css 34*1024 / gzip 122*1024；

桌面开发版（`npm run tauri dev`）满足 `hasTauriRuntime()`，`runtimeInitialValue` 在非 PROD 下返回 fixture，
而 `useDomainResource` 的持久化 effect 在 hydrate 后会把**当前值**写进 SQLite —— 于是 dev fixture 被写进了
和正式安装版共用的同一个库（macOS 上同一 app identifier 的数据目录）。安装正式版后读到的就是这些数据。
本轮只提供了「清空财务数据」按钮兜底；真正的根治（dev 不写库 / dev 用独立数据目录 / fixture 只用于浏览器预览）

- 新增 kind `approved`（展示为"已批准"），并抽出 `countsToBudget(kind)`：
  只有 `necessary` / `approved` 计入预算；`removeBillEffects`/`applyBillEffects` 改用它，
  避免"已批准账单被删却不回滚预算"的旧坑。
- 账单编辑下拉、筛选 chip 同步加"已批准"；chip 颜色改为 `kindChipClass` 映射表。

## DEV fixture 隔离（同日）

诉求：解决 dev fixture 写入生产库的问题。

### 根因
`tauri dev`（debug profile）与 `tauri build`（release）共用同一个 `app_data_dir()/life-os.sqlite3`。
dev 模式下前端 fixture 作为 `useDomainResource` 初始值，用户一操作就把 fixture 连同数据写进这个共享库，污染生产库。

### 改动

  release 用 `life-os.sqlite3` + `backups`；setup 中数据库与备份目录都改走该函数。
- 新增单测 `debug_builds_isolate_from_the_production_database`。
- 文档：`doc/requirements-current.md` §4.4、`doc/feature-entry-map.md`（持久化排障要点/症状索引/§6.2/§7）、`progress.md`。

### 约定
- debug 库 `life-os.dev.sqlite3` 与生产库彻底隔离，fixture 随便写 dev 库都不影响生产。
- 前端 `import.meta.env.PROD` 编译期分支保持不变（生产构建仍删除 fixture、tree-shake）。
