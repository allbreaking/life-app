# Life-OS 现状需求文档

> 文档类型：基于现有代码反向整理的 As-Is 需求基线  
> 基线日期：2026-08-16  
> 适用版本：`0.1.0`  
> 事实优先级：运行代码与测试 > `docs/specs/` 专项规格 > `docs/development/` 总体规格 > 原型展示文案

## 1. 文档目的

本文档描述 Life-OS 当前仓库中已经存在的产品能力、业务约束、数据副作用和已知缺口。它不是未来愿景清单；后续新增、修改或排查功能时，应先确认需求状态，再通过同目录的 `feature-entry-map.md` 定位实现入口。

状态定义：

- **已实现**：生产构建存在可用入口，业务状态可按设计持久化或产生明确桌面副作用。
- **部分实现**：主要界面或局部流程存在，但规格中的联动、编辑能力或持久化尚不完整。
- **仅开发演示**：只在非生产构建显示 fixture/示例，不能视为生产能力。
- **占位**：入口存在，但主动禁止业务写入或提示后续接入。

## 2. 产品定位与目标

Life-OS 是一个 local-first 的个人认知与生活管理桌面应用。产品通过六个业务模块管理原则、财务、物品、社交、投资信息，并以“今日总览”提供聚合视图。

当前目标：

1. 将不同生活领域的数据保存在本地 SQLite 中。
2. 以规则和派生指标帮助用户发现风险，不替用户做价值判断或投资决策。
3. 通过严格输入校验、IPC 白名单、幂等写入和本地备份降低数据与安全风险。

非目标：

- 不提供云同步、多用户协作或账号体系。
- 不执行真实证券交易，也不提供买卖建议。
- 不对社交关系打分，不使用“断联倒计时”。
- 不允许前端访问通用网络、任意文件或 shell。
- 生产构建不注入演示业务数据。

## 3. 用户与运行环境

- 目标用户：单机使用 Life-OS 的个人用户。
- 主要运行形态：Tauri 2 桌面应用；核心桌面增强针对 macOS。
- 窗口基线：默认 `1440×900`，最小 `900×640`。
- 浏览器/Vite 模式：用于开发和组件验证；SQLite、行情、备份、系统通知及原生菜单等能力不可用或安全降级。

## 4. 全局功能需求

### 4.1 应用壳与导航 — 已实现

- 左侧固定展示六个模块入口：今日总览、人生地图、财务、物品、社交、投资。
- 点击模块后在单页主内容区切换，不使用 URL 路由。
- 最后选择的模块写入 `window.localStorage`，重开界面时恢复；无效值回退到今日总览。
- 页面提供“跳到主内容”键盘链接和可见焦点样式。
- 页面头部提供“数据保护”入口。

副作用：模块选择仅读写浏览器 `localStorage`；模块业务数据不保存在 `localStorage`。

### 4.2 快捷录入 — 占位

- `⌥ Space`、原生应用菜单“打开快捷录入”可打开单层模态框。
- `Escape`、关闭按钮或点击遮罩可关闭；Tab 焦点受限于模态框，关闭后恢复原焦点。
- 系统级快捷键注册失败时应用仍可启动。
- 当前输入框被禁用，不产生业务数据，也未复用领域写入服务。

### 4.3 原生菜单与 macOS 菜单栏 — 已实现

- 应用菜单提供“打开快捷录入”“回到今日总览”和退出。
- 编辑菜单使用系统角色提供撤销、重做、剪切、复制、粘贴和全选。
- macOS 菜单栏状态项为占位入口，菜单提供“打开快捷录入”和“回到今日总览”两个快捷动作。
- 原“下一待办”状态项及“标记完成”能力已随日程模块一并移除。

### 4.4 领域状态持久化 — 已实现

- React 组件通过 `useDomainResource` 使用白名单资源键加载和替换数据。
- 前后端均执行结构或白名单校验；集合保存到 `domain_entity`，标量/空集合保存到 `domain_value`。
- 每次替换生成 `requestId`，Rust 在同一 SQLite 事务内写入资源和 `command_receipt`，重复请求幂等。
- 首次读取资源时可从旧 `module_state` 一次性导入，并记录迁移标记。
- 单个资源序列化后不得超过 256 KiB。
- 生产环境无存储值时使用空集合、空字符串或零值；不会覆盖已有 SQLite 数据。
- 开发构建（debug profile，如 `tauri dev`）使用独立的 `life-os.dev.sqlite3` 数据库与 `backups-dev` 备份目录，演示 fixture 只写入开发库，不写入生产库 `life-os.sqlite3`。

注意：当前 hook 采用前端乐观状态，IPC 保存失败只写入控制台，界面不会自动回滚或统一显示失败提示。

### 4.5 数据保护 — 已实现（仅桌面版）

- 用户可列出、创建和恢复应用管理目录内的 SQLite 快照。
- 备份 ID 必须匹配 `life-os-<10~20位时间戳>.sqlite3`，最大文件大小 512 MiB。
- 恢复前需要用户确认，并校验路径、符号链接、数据库完整性、外键和 schema。
- 恢复前创建回滚点；失败时保留恢复前数据；成功后重载应用。

### 4.6 系统通知 — 后端能力已实现，业务入口未接线

- typed IPC 和 Rust 服务支持七类白名单告警通知。
- 通知按 `entityId + alertType + occurrenceAt` 去重；成功才保留投递收据，失败允许重试。
- 当前业务组件没有调用 `deliverNotification`，因此不会从六模块自动弹出系统通知。

### 4.7 视觉告警与无障碍 — 已实现

- Crimson、Amber、安全价蓝色表示不同级别或类型的告警。
- 告警容器可使用统一呼吸动画；系统启用 reduced motion 时停止动画并保留颜色和文字。
- 模态框、跳转链接和投资自绘选择器覆盖主要键盘操作。

### 4.8 整体页面风格 — 目标要求（低摩擦、透明感）

整体体验关键词为：**安静、轻盈、直接、可信**。页面应降低用户理解和操作成本，并通过清晰的层级、状态与结果反馈形成透明感。“透明感”同时包含视觉上的轻透层次与信息上的可理解、可追踪，不等同于大面积模糊或降低可读性。

#### 4.8.1 低摩擦体验

- 高频操作应在当前上下文内完成，优先使用原地编辑、行内表单、直接切换和就近反馈；除数据恢复等高风险操作外，不增加多余确认步骤。
- 一个操作尽量只有一个明确主动作；次要操作弱化，危险操作使用稳定的 Crimson 语义，避免同一层级出现多个争夺注意力的按钮。
- 输入项只要求完成当前任务所必需的信息；提供合理默认值、清晰占位提示和即时校验，不要求用户理解数据库、模块或技术术语。
- 用户提交后应立即看见“进行中、成功或失败”状态；失败信息应出现在触发位置附近，保留用户草稿，并说明可以如何修正。
- 页面切换、编辑与保存尽量不跳页、不打开嵌套弹窗、不打断滚动位置；临时状态应支持取消和 `Escape` 退出。
- 相同动作在不同模块中保持相同文案、位置和行为，例如“保存 / 取消”“编辑 / 删除”以及选中、完成、告警状态。
- 空状态直接说明当前没有什么以及下一步可以做什么，不展示伪数据，不让用户猜测入口。

#### 4.8.2 视觉透明感

- 使用明亮、低饱和的中性色背景承载内容，卡片和浮层可使用轻度透明或半透明表面形成空间层次；透明度不得导致文字、表格和输入内容与背景混淆。
- 视觉层级主要依靠留白、色面、圆角和轻微明暗变化表达，减少厚重边框、强阴影、渐变堆叠和高对比装饰。
- 卡片层级保持克制：基础卡片接近无阴影；只有悬浮菜单、模态框和需要脱离页面的临时层使用柔和阴影或适度背景模糊。
- 透明表面之下的背景应简单、稳定，不放置高频纹理或高对比内容；无法保证可读性时应退化为不透明浅色表面。
- 主色使用现有 Sky Blue 表达当前选择、焦点和普通反馈；Crimson、Amber 只用于真实风险或提醒，不作为大面积装饰色。
- 文本至少分为强标题、正文、弱说明三级；核心数据和操作不得仅依赖透明度或颜色区分。
- 动效只用于说明状态变化和操作结果，持续时间短、幅度小；避免纯装饰漂浮、视差或长时间模糊动画。启用 reduced motion 时完整保留信息含义。

#### 4.8.3 信息透明感

- 页面明确显示数据来源、最后更新时间和当前状态；例如行情需展示“新浪行情”和行情时间，派生指标需说明其口径。
- 自动行为必须可解释：用户应能知道数据为什么被分类、告警为何出现，以及保存失败后数据是否保留。
- 业务规则在用户触发相关操作时就近展示，不把关键限制隐藏在帮助文档中。例如 Q1 上限、目标价关系和食物到期日要求。
- 状态变化应可追踪到稳定实体，跨入口操作使用同一数据源，不展示彼此矛盾的副本。
- 不使用“已保存”“已完成”等确定性文案掩盖仍在进行或已经失败的副作用。

#### 4.8.4 布局与组件约束

- 桌面端保持稳定侧栏和单一主内容区；同一页面优先采用少量清晰分区，不堆叠多层容器。
- 内容宽度、卡片间距、圆角、输入高度和状态颜色由共享 token 控制，禁止各模块随意创建近似值。
- 表单控件默认弱边框或无边框，通过背景和 `focus-visible` 表达交互状态；键盘焦点必须清晰，不得为了“轻”而移除可访问性反馈。
- 表格或密集列表优先保持列对齐、稳定行高和就近操作；窄屏允许横向滚动或转为单列，但不得隐藏关键字段。
- 模态框只用于需要中断背景操作的短流程；背景遮罩保持轻量但必须清楚表达当前焦点层。

#### 4.8.5 验收标准

- 用户从任一模块进入核心新增或编辑流程，最多一次入口点击即可开始输入；常规保存不出现二次确认。
- 所有可写表单均能在提交位置看到处理中、成功或失败反馈；校验失败不清空合法草稿。
- 页面不存在无业务含义的强阴影、厚边框或高饱和大色块；浮层与基础内容的层级一眼可辨。
- 半透明表面在浅色和复杂背景上均保持正文可读；无法满足对比度时自动或直接使用实色表面。
- 所有交互控件支持可见的 hover、active、disabled 和 `focus-visible` 状态；仅键盘可完成主要操作。
- 在 `prefers-reduced-motion: reduce` 下不播放非必要动画，告警和状态仍能通过文字、图形或静态色面识别。
- 同类组件跨模块的间距、圆角、颜色语义和操作顺序一致，并优先复用共享样式或 token。

当前实现已具备浅色背景、无边框输入、圆角卡片、克制阴影、统一状态色和 reduced-motion 降级，部分符合上述方向；卡片半透明层次、统一的保存反馈以及跨模块组件一致性仍需在后续 UI 规格和实现中继续对照完成。

## 5. 业务模块需求

### 5.1 今日总览 — 部分实现

生产能力：

- 两个每日待办清单（每日输出、地球online日常任务），每条内容可新增、原地编辑、删除；完成状态按本地日期记录（`completedOn`），隔天自动刷新为未完成，分别写入 `dashboard.dailyOutput`、`dashboard.dailyTasks`。
- 预警聚合只读聚合其他模块数据，不新增业务数据：物品（食物过期/临期）、财务（月度预算超支或领先时间进度）。生产与开发环境均显示，无预警时展示空状态。预算未配置（`finance.budgetCents` 为 0）时不产生财务预警。
- 即将到来的重要日期只读聚合社交联系人带 `importantDate` 的记录（自由文本，不做倒计时推算），无记录时展示空状态。
- “今日待办”卡片同步 macOS 系统日历（EventKit）：点击「同步日历」读取当天日程（含全天与定时事件）和当天到期或逾期未完成的提醒事项；提醒事项可勾选完成/取消完成并回写到系统提醒事项。首次使用会弹出日历与提醒事项两个系统授权框，未授权时卡片内展示降级提示。浏览器/非 macOS 环境不提供该能力并显示说明。
- 日程的完成状态仅在 Life-OS 本地记录（系统日历事件无完成字段）：勾选后写入 `dashboard.completedEvents`（`eventId → 完成日期` 对象标量），按本地日期判断完成，隔天自动刷新为未完成；不写回系统日历。

占位：无。

仅开发演示：本月北极星仍为 fixture，不从其他模块实时聚合。

### 5.2 人生地图 — 部分实现

- Being 与 Doing 两类原则分别展示和新增。
- 新原则要求领域 1–30 字、内容 1–200 字，保存后写入 `compass.principles`。
- 生产环境无默认原则。

未完整实现：原则编辑/归档、阶段北极星、演进日志的新增/编辑/归档以及从投资沉淀日志。Life Changelog 当前仅开发演示且新增按钮禁用。

### 5.3 财务 — 已实现基础记账、账单与预算，部分能力为演示

- 快捷记账的金额输入框只填写金额数值（最多两位小数）；其前方提供 `− / +` 收支方向切换，方向与金额合成有符号字符串后转换为整数分存储；零值和非安全整数拒绝。
- 选择 `−` 且为必要支出时，立即把金额绝对值累加到当月已用预算；选择 `+` 记录收入，不计入预算消费；`+` 时必要/非必要切换禁用。
- 选择 `−` 且为非必要支出时只进入待评估队列：**不写入 `finance.transactions`、不计入已用预算**，此时它只是一笔待审批的支出意向。
- 必要支出、已批准支出与收入写入 `finance.transactions`，记录稳定 ID、有符号金额、备注、类型（`necessary / approved / unnecessary / income`，其中 `unnecessary` 仅用于兼容旧数据）和本地 `YYYY-MM-DD` 日期。只有 `necessary` 与 `approved` 计入已用预算。
- 一进一出拦截：备注含「外套 / 大衣 / 衣服 / 上衣 / 毛衣 / 衬衫 / 卫衣 / 夹克 / 羽绒服 / 西装 / 裤 / 裙 / 鞋 / 帽 / 围巾」等衣物词的支出一律先拦截，不立即入账也不进队列；页面展示待处理面板，列出 `items.items` 中的物品，用户清理 1 件后才完成记账（清理动作会写入 `items.items`）。物品库为空时提示先去物品模块添加，也可取消本次支出。收入不受该规则影响。
- 月度预算卡自上而下展示月度已用/预算、两条进度条（预算消费进度、当月时间进度，按本地当前时间实时计算）与动态日均预算：当月日均预算 `= 月度预算 ÷ 当月天数`，剩余可支配 `= (月度预算 − 已用) ÷ 剩余天数（含今天）`，随日期与消费实时重算；月度预算为 0 时视为未配置，显示“未设置月度预算”而不再按 100% 消费告警。
- 财务页工具栏提供「清空财务数据」（两步确认），用于清空本地安装后残留的月度预算、已用、待评估队列、账单、订阅与目标进度，便于从演示/测试数据恢复到空状态。
- 周期订阅写入独立资源 `finance.subscriptions`（名称 1–60 字、正数金额、下次扣费日 `YYYY-MM-DD`）。按下次扣费日计算剩余天数：当天或逾期为 Crimson、3 天内为 Amber、其余为 normal。
- 财务页顺序为：工具栏（「全部账单」「清空财务数据」）→ 500 元积累目标 → 概览行（月度预算 / 周期订阅预警 / 非必要支出待评估队列）→ 快捷记账 → 一进一出拦截面板（触发时）→ 周期订阅管理。不使用 URL 路由，卡片无“最近交易/今日支出”。
- 财务概览的“周期订阅预警”卡片只读，仅列出处于预警级别的订阅并展示金额与剩余天数，按最高级别闪烁；不提供增删改。
- 页面底部的“周期订阅管理”卡片承载完整订阅列表与新增、行内编辑名称/金额/日期、删除操作，新增/编辑校验失败不清空草稿。
- 财务页提供「全部账单」入口；账单列表支持按备注子串搜索、按时间筛选（全部时间 / 今天 / 近 7 天 / 本月 / 自定义起止日期）以及按必要支出、已批准、非必要支出、收入筛选，展示当前结果条数、支出与收入合计；搜索、筛选、区间均为瞬时界面状态。
- 账单行支持原地编辑日期、备注、类型和金额，或直接删除；保存与删除会同步回滚旧记录、应用新记录对本月已用预算或待评估队列的影响，保证账目与预算一致。备注 1–200 字、金额需为非零有效数值、日期需为 `YYYY-MM-DD`。
- 待评估队列逐项审批：每项提供「通过」与「拒绝」。
  - **通过**：预算结余足够时，金额计入本月已用预算，并**自动生成一条 `approved`（已批准）账单**进入「全部账单」；旧数据若已关联既有账单，则改为把该账单标记为已批准。结余不足则保留该项并提示差额。
  - **拒绝**：只把该项移出队列，**不生成任何账单**；旧数据若已关联账单则一并删除。
  - 两种审批都不改变该笔支出的金额与备注。
- 队列底部「全部通过」批量放行：预算结余覆盖待评估总额时，为未关联账单的项补建 `approved` 账单、把已关联的改为已批准，一次性计入预算并清空队列；否则保留队列并提示差额。
- 消费比例达到 100% 为 Crimson；未满 100% 但领先本月时间进度为 Amber。
- 月度预算金额可在预算卡片原地编辑；支持保存、取消和 `Escape`，仅接受大于 0、最多两位小数的金额，保存后即时重算消费比例与预警。
- 长期积累目标固定为 3000 份、每份 500 元；初始进度为 1500 份。财务页展示份数、金额与百分比进度条，用户只能通过 `+` / `−` 两个按钮每次变动 1 份，结果保持在 0–3000 份；到达上限或 0 时对应按钮禁用。
- 点击 `+` 播放彩带特效，点击 `−` 播放卡片抖动与红色负反馈特效；`prefers-reduced-motion: reduce` 下不播放动画，仍通过状态文字反馈变动结果。
- 已完成份数写入独立资源 `finance.goalCompletedUnits`；合法 +1/−1 经 typed IPC 单资源事务持久化。

已知差异：快捷记账卡右下角的拦截规则说明与防囤货拦截示例仅在开发构建显示（Amber 呼吸动画），生产不注入；一进一出拦截本身在生产同样生效；月度预算相关资源分别异步替换，月末结算和后端单资源事务不是同一个跨资源事务；全部账单仅记录本地手动记账，不含自动归类结果；订阅预警不自动推进扣费日，需用户手动维护下次扣费日期。

### 5.4 物品 — 已实现列表管理与食物预警

- 支持消耗品、保养品、使用时期品、固定资产和食物。
- 所有物品必须填写名称和位置；名称/位置最长 200 字，详情最长 500 字。
- 食物必须填写 `YYYY-MM-DD` 到期日，并在独立完整清单展示。
- 到期日按本地日历中午计算，避免时区边界漂移：已过期或 3 天内为 Crimson，4–7 天为 Amber，其余正常。
- 普通物品采用名称、分类、位置、详情和操作五列列表；食物采用名称、位置、到期日、状态和操作五列列表。
- 普通物品与食物均支持当前行编辑、取消和删除；保存与删除按稳定 ID 替换对应领域资源，食物到期日保存后即时重算预警。

未完整实现：`opened_at`、`shelf_life_days` 为旧结构规划，当前资源 schema 未单独保存；消耗周期学习/预测卡片是固定演示。

### 5.5 社交 — 已实现基础人物卡片

- 用户可新增姓名、关系、备注和可选重要日期；姓名 1–100 字，备注最长 500 字。
- 人物卡展示关系、最后互动、偏好/互动备注和重要日期。
- 不计算关系评分或断联倒计时。

未完整实现：人物编辑/删除、结构化互动历史、日期计算、重要日期自动触发通知。新记录的“上次互动”固定为“刚刚添加”。

### 5.6 投资 — 已实现，当前最完整模块

#### 5.6.1 投资 SOP

- 在原卡片内编辑、保存、取消；`Escape` 取消。
- 保存时 trim，要求 1–500 字；展示保留换行并折行。
- 草稿只保留在组件状态，保存后替换 `trade.sop`。

#### 5.6.2 观察列表与行情

- 新增标的要求六位 A 股或五位港股代码、不重复代码、1–100 字名称及合法三档目标价；新增区不录入或校验安全价，新记录固定保存 `safety: 0`。
- 新增目标区间只要求：`乐观目标价 ≥ 中枢目标价 ≥ 悲观目标价 > 0`。已有标的编辑安全价时仍要求 `0 ≤ 安全价 < 中枢目标价`。
- 新增必须先由 Rust 从固定主机 `hq.sinajs.cn` 成功取价，再写入观察列表。
- 支持按稳定 ID 原行编辑代码、名称、三档目标价和安全价；代码改变时重新取价，失败保留原记录。
- 删除前检查全部当前/已清仓持仓引用；有引用拒绝删除，无引用不级联地删除观察标的。
- 当前价达到中枢目标价显示目标告警；低于或等于安全价显示安全告警；否则观察中。
- 每个观察标的支持 0–10 个标签，单个标签 1–20 字；新增和原行编辑均可用中英文逗号分隔录入，保存时去空白、去空项并按首次出现顺序去重。
- 观察列表可按“已达中枢目标价 / 已跌破安全价 / 观察中”筛选，也可按现有标签筛选；两种条件取交集后每页显示 10 条。筛选只影响观察表格，不影响完整观察列表的行情刷新、持仓来源和引用保护。
- 观察列表可按股票代码或名称子串搜索，名称中的拉丁字母忽略大小写；搜索与价格状态、标签取交集后再分页，搜索词属于瞬时界面状态。
- 现价下方依次展示距乐观、距中枢、距悲观百分比，统一口径为 `(对应目标价 / 现价 - 1) × 100%`。
- 每个观察标的可选记录商业模式、盈利能力、财务稳定性、现金流四项 0–5 星整数评分；新增和原行编辑均可留空，留空显示“未评分”，0 分与未评分明确区分。旧“现金流与分红”评分读取时兼容为现金流评分，旧当前估值评分丢弃。
- 观察列表以星级摘要展示四项评分，不展示安全价、当前估值或分红评分；安全价仍保留在已有标的编辑、价格状态筛选和持仓公式中。
- 列表默认按加入时间倒序，最新加入的标的置顶；也可按任一评分维度高到低或低到高稳定排序，未评分固定置后。排序在搜索、状态和标签筛选之后、分页之前执行，排序条件不持久化。
- 观察标的新增区使用基础信息、价格、评分三行均匀网格；输入框和评分下拉复用页面浅底、无边框、圆角与可见焦点风格，列表名称列保持紧凑并与其他列均衡。
- 行情不自动轮询，由用户点击「刷新行情」手动批量拉取最新快照；支持六位 A 股与五位港股混合，行情时间如实展示（新浪免费快照存在秒级延迟，非交易时段返回上一交易日收盘价）。
- 单次最多 50 个不重复代码；网络错误、单只标的数据无效或停牌时跳过该只并保留其最后成功价格，不影响其余标的。
- 旧记录缺少乐观/悲观价或标签时，分别以内存中的中枢价或空标签数组补齐，不主动写迁移。

#### 5.6.3 持仓

- 新持仓只能选择观察列表稳定 ID，并只录入有限正数建仓价与正整数股数。
- 自绘 listbox 支持点击、方向键、Escape，并可按股票代码子串搜索候选项；标的被删除后自动修正选择。
- 当前持仓支持原行编辑建仓价与股数、清仓或直接删除；已清仓列表只读展示股数。
- 删除当前持仓不会生成历史；已清仓记录也可按稳定持仓 ID 删除，两种删除都不级联观察标的。
- 清仓保存有限正数清仓价、当日本地日期和已实现盈亏百分比，并由 Tab 过滤到已清仓列表。
- 同一 `trade.positions` 资源保存当前与已清仓记录，避免跨资源搬运。旧记录缺少股数时按 0 补齐，展示为「—」。

派生公式：

- 持有市值 `= 股数 × 建仓价`
- 浮动盈亏 `% = (现价 / 建仓价 - 1) × 100`
- 距中枢目标价 `% = (中枢目标价 / 建仓价 - 1) × 100`
- 距安全价 `% = (建仓价 / 安全价 - 1) × 100`
- 已实现盈亏 `% = (清仓价 / 建仓价 - 1) × 100`
- 当 `建仓价 > 安全价` 时，减半仓价格 `= 2 × 建仓价 - 安全价`

所有公式均为前端纯派生，不构成交易建议，不触发交易或网络请求。

#### 5.6.4 每日复盘

- 以本地 `YYYY-MM-DD` 日期唯一；同日再次提交覆盖当日内容。
- 内容 trim 后要求 1–1000 字。
- 支持按原日期原行编辑、取消和删除，保存到 `trade.reviews`。

### 5.7 健康 — 已实现今日记录、月历与详情

- 今日卡片固定操作本地今天，天气（晴/多云/阴/小雨/雨/雪）、温度、湿度、睡觉/起床时间、运动类型与分钟、情绪四选一与一句话情绪记录，输入即保存。
- 睡眠时长跨午夜计算；天气、睡觉时间段与情绪三项都填写时顶部状态为“已记录”，否则“待补充”。
- 经期面板支持标记今天为经期、单选经血量、多选症状；取消标记时清空经血量与症状。
- 身体事件（皮肤/肠胃/牙齿/用药/其他身体状况）各有预置标签，选标签后可填可选备注再保存；未选标签不写入。
- 健康月历以周一起始渲染 42 格，非当月置灰、今天高亮、事件日期按类型着色、经期日显示连续条带；点击日期在右侧详情面板编辑。
- 情绪使用标准值 `happy / anxious / neutral / sad`，旧 emoji 读取时由 `normalizeMood` 兼容。
- 数据按本地 `YYYY-MM-DD` 组织为 `health.records` 单资源，生产环境初始为空对象。

## 6. 数据与技术需求

### 6.1 技术选型

| 层 | 当前选型 | 用途 |
|---|---|---|
| 桌面壳 | Tauri 2 + Rust 2024 | 窗口、原生菜单、状态项、系统快捷键、IPC、安全边界 |
| 前端 | React 19 + TypeScript 5.8 | 单页组件、瞬时 UI 状态、派生视图 |
| 构建 | Vite 7 | 开发服务器与生产构建 |
| 校验 | Zod 4 + Rust 手工校验/Serde | 前端输入、IPC 响应和后端白名单 |
| 数据库 | SQLite + rusqlite（bundled） | 本地持久化、事务、迁移、备份 |
| HTTP | reqwest + rustls | 仅 Rust 固定行情 adapter |
| 测试 | Vitest、Testing Library、Rust tests、Node 静态审计 | 纯函数、组件、数据库和发布门禁 |

### 6.2 数据一致性

- SQLite 启用 foreign keys，迁移版本当前为 3。
- 运行时主要读写通用 `domain_entity`/`domain_value`；`001_initial.sql` 中的领域表多数是架构基础，目前组件未直接使用。
- 数组实体优先使用对象 `id` 作为实体 ID；无 `id` 的数组（例如按日期复盘）使用 `row-<位置>`，每次整体替换后重建。
- 跨多个资源的前端操作不是原子事务。例如月度预算相关多个资源分别异步替换，异常中断可能产生短暂或持久不一致。

### 6.3 安全

- CSP 不允许通配源；主窗口 capability 仅 `core:default`。
- 前端资源键和后端资源地址均为固定白名单。
- 行情服务只接受五位港股或六位 A 股代码，分别映射到 `hk` 与沪深北市场前缀，并限制代码数量、响应大小和字段格式。
- 备份恢复拒绝路径穿越和符号链接。
- 系统通知限制类型、标识符、文本长度、控制字符和时间格式。
- 代码不拼接 SQL 用户值，不执行 shell 命令。

## 8. 已知风险与排查优先级

1. `useDomainResource` 保存失败不回滚且只 `console.error`，用户可能认为已经保存；涉及“重启后丢失”时优先检查这里和 Tauri 控制台。
2. 多资源操作由前端连续写入而非单个后端事务；涉及财务结算不一致时应同时核对相关资源。
3. 生产与开发视图差异明显；排查“生产缺少卡片/数据”前先确认它是否只是 fixture。
4. 业务通知尚未接线；“有告警但无系统通知”是当前预期，不是通知 adapter 必然故障。
5. 快捷录入是安全占位；无法输入或保存是当前预期。
6. `001_initial.sql` 领域表与实际通用资源存储并存；排查运行数据时优先查 `domain_entity`/`domain_value`，不要只查旧领域表。
7. 行情能力仅桌面版可用；数据源为新浪免费快照，存在秒级延迟，非交易时段返回上一交易日收盘价，行情时间会如实展示。
